## Local preview

```powershell
npm install
npm run web
```

Without an API URL, the app uses 12 bundled, original abstract wallpapers. Favorites and appearance are saved locally. Preview does not simulate login or owner access. The working app includes Discover with masonry and filters, featured day/week/month picks, a paged immersive feed, details, collections/month archive, and Profile.

## Android

Install Android Studio, SDK 36, a Google Play emulator, and JDK 17. Start the emulator, then:

```powershell
npm run android
```

This builds the native Google login integration and local Kotlin wallpaper module. Applying supports home screen, lock screen, or both. `npm run start` restarts Metro for an already installed development build. Expo Go supports a limited preview; use a development build for real authentication and applying.

The app uses Expo SDK 54 / React Native 0.81 / NativeWind 4.2 / Tailwind 3, pinned together with a lockfile. A custom prebuild plugin shortens CMake output paths to handle this Windows workspace's long path. Native generated directories are ignored and can be recreated.

### Release APK for a phone

```powershell
cd apps/mobile
npx expo prebuild --platform android --no-install
cd android
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
.\gradlew.bat app:assembleRelease -PreactNativeArchitectures=arm64-v8a
```

The APK lands in `apps/mobile/android/app/build/outputs/apk/release/`. It is signed with the debug key, which is fine for sideloading but not for the Play Store. The icon and splash marks are regenerated with `python scripts/generate-logo.py` (needs Pillow).

## Connect live services

1. Copy each `.env.example` to `.env` in `apps/api` and `apps/mobile`.
2. Follow the Google, Neon, and R2 guides above. All secrets stay in the API environment.
3. `npm run db:migrate`
4. `npm run api:dev`
5. Set mobile `EXPO_PUBLIC_API_URL=http://10.0.2.2:4000` for the Android emulator and the Google web client ID. Restart Metro.
6. Sign in as `sahilsensei.work@gmail.com` → You → Studio. Publish your first artwork, create collections, and schedule featured picks.

To fill an empty catalog in one go, put images in `wallpapers/` named `<Theme>+<Style><number>.png` and run `npm run db:seed`. Each theme becomes a curated collection; running it again skips files already published.

Live likes persist in PostgreSQL; Studio is enforced by the server using verified Google identity. Originals and generated previews live in R2. A live catalog starts empty and never silently falls back to preview content after an API failure.

Neon does not host the Node API. Deploy `apps/api` separately behind HTTPS, run the migration step, and set the deployed URL in the client before release. The API build command is `npm run build:api`; start it with `npm run start -w @wallp/api`. Keep SQL migrations with your deployment package.

## Checks

```powershell
npm run typecheck
npm test
npm run build:api
npm run export:web
npm run export:android
```

For a real disposable PostgreSQL database, set `TEST_DATABASE_URL` before `npm test`. The integration test uses an isolated temporary schema. Do not use production credentials for tests. Unit and route tests run without credentials; Google, Neon, R2, and actual wallpaper application require external integration checks.

## Layout

```
apps/mobile     React Native app + local Android wallpaper module
apps/api        Fastify API + SQL migrations + security/upload tests
packages/shared Catalog types and input schemas
scripts         Reproducible original abstract artwork generator
docs            Requirements, setup, testing, and handoff
```

Original sample assets are generated by `node scripts/generate-art.mjs`. The app generates no artwork at runtime. Windows + Android is the fully supported development target; iOS uses manual wallpaper application and requires its OAuth client before building.
